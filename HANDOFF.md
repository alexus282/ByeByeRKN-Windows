# ByeByeRKN Windows — handoff

## Цель и ограничения

Портировать MVP Android-приложения ByeByeRKN на Windows: полноценное GUI-окно с настройками, AmneziaWG + скан эндпоинтов + регистрация WARP. MASQUE и продвинутый мониторинг — отдельный этап.

- Android (`app/`) **не трогать** — там эталон алгоритмов.
- Ядро туннеля — внешняя зависимость `github.com/amnezia-vpn/amneziawg-go`, не копия в репозитории.
- Интерфейс — Gio (`gioui.org`), без CGO и без WebView2. Оформление повторяет Android-приложение в стиле Amnezia.
- Комментарии в коде — на английском, коротко объясняют «почему». Тесты обязательны.
- Адаптер и маршруты меняет служба `ByeByeRKN`; окно работает без прав. UAC нужен только установщику. Portable-режим (без службы) по-прежнему требует администратора.

## Что реализовано

| Пакет | Назначение |
|---|---|
| `awg` | пресеты обфускации, QUIC/STUN/DNS/SIP I1, UAPI и wg-quick строки |
| `catalog` | каталог серверов и портов WARP |
| `probe` | handshake-пробы и параллельный сканер |
| `warp` | регистрация устройства, WARP+, split ClientHello |
| `wintunnel` | Wintun-адаптер: адреса, MTU, DNS, маршруты, откат, диагностика |
| `store` | JSON настроек, аккаунта и last-good: `%AppData%` в portable, `%ProgramData%` у службы |
| `engine` | контроллер, UAPI/IpcGet, trace, детектор зависаний |
| `ui` | окно на Gio: главная с кольцом, настройки, журнал, диалоги, тосты |
| `control` | JSON-over-named-pipe: сервер с движком и клиент, который использует окно |
| `winsvc` | хост службы: SCM, запуск/остановка сервера, ожидание Stop/Shutdown |
| `install` | установка и удаление: файлы, служба, ACL, ярлык, запись в «Программы и компоненты» |
| `cmd/setup` | однофайловый Setup.exe: встроенные программа и `wintun.dll`, UAC один раз |
| `tray` | значок в трее на Win32: меню, подсказка, уведомления, WM_ENDSESSION |
| `instance` | один экземпляр на пользователя, события «показать» и «закрыться для удаления» |
| `winres` | иконка приложения |

GUI: русский язык, тёмная тема Android-приложения (`ui/theme.go` — палитра, шрифты Segoe UI и
Consolas из системной папки). Три раздела: «Главная» (кольцо подключения, статус, карточка
сервера), «Настройки» (карточки с переключателями и диалогами выбора), «Журнал» (те же строки,
что нужны для разбора проблем). Нижняя навигация, как на телефоне; на широком окне главная
раскладывается в две колонки.

Трей: иконка приложения с точкой состояния (серая — выключено, жёлтая — подключение, бирюзовая —
подключено, красная — ошибка), меню «Подключиться/Отключиться», «Открыть ByeByeRKN», «Выход».
Крестик по умолчанию прячет окно в трей; переключатель «Сворачивать в трей» в настройках меняет
это на полный выход. Выход из меню и завершение сеанса Windows сначала снимают маршруты и DNS.

Установленная версия: служба `ByeByeRKN` (LocalSystem, автозапуск) владеет движком, настройками
и WARP-аккаунтом; окно запускается без прав и общается по `\\.\pipe\ByeByeRKN` (JSON-строки,
доступ только установившему пользователю, SYSTEM и администраторам). Команды: connect, disconnect,
settings, export, warp-plus, forget-server, reset-account; обратно идут status, traffic, log,
settings, account. UAC нужен только Setup.exe. Portable-режим остался: если службы нет, окно,
запущенное от администратора, поднимает движок само и пишет настройки в `%AppData%`.

## Последние важные исправления

1. **DAD на Wintun.** Адрес `172.16.0.2/32` оставался `Tentative`, из-за чего Windows выдавала `unreachable host` даже при успешном handshake. В `wintunnel.Configure` выставлены `dadtransmits=0 routerdiscovery=disabled`. Это было главным исправлением работоспособности.

2. **Порядок teardown.** В `engine.establish` перед созданием следующего адаптера сначала вызывается `net.Teardown()`, и только потом `closeSessionLocked()`. Закрытие Wintun раньше `netsh` приводило к ошибкам удаления маршрутов/DNS и переносу старых маршрутов на новый адаптер с тем же индексом.

3. **Маршруты.** Вместо `0.0.0.0/0` используются `0.0.0.0/1` + `128.0.0.0/1`, для IPv6 — `::/1` + `8000::/1`. Метрика интерфейса `0`. IPv6 MTU не ставится ниже 1280 (Windows запрещает).

4. **Проверок Telegram нет.** Раньше после поднятия туннеля шёл MTProto-обмен и при неудаче маршрут помечался ограниченным, хотя Telegram работал. Теперь единственное доказательство — трафик, реально прошедший через WARP (`warp=on` в trace). Никаких задержек после подключения и никаких плашек «может не работать»: `colo` показывается только как приблизительная справка.

5. **Сервер и выход в карточке.** Раньше вместо сервера показывался город выхода, и его принимали за настоящий сервер. Теперь в карточке две строки: `Сервер · <адрес:порт>` (реальный WARP-эндпоинт туннеля) и `Выход · <город> (<colo>, <страна>)` — приблизительная точка выхода Cloudflare. В трее подсказка тоже начинается с адреса сервера.

6. **Один экземпляр и трей.** Первый запуск создаёт именованный event с низкой меткой целостности, поэтому второй (непривилегированный) запуск может его разбудить; окно показывает уже работающий процесс. В трее при закрытии окна остаётся VPN, а не пустой процесс.

7. **Заголовок окна.** Gio сам иконку из ресурсов не берёт (он ищет её под другими ID), поэтому `ui/native_windows.go` ставит её через `WM_SETICON` и красит заголовок через DWM. Вызовы к чужому окну — только асинхронные (`PostMessage`, `ShowWindowAsync`) или из отдельной горутины: поток Gio ждёт обработчик события, и синхронный `SendMessage` из него вешает окно.

8. **Светящееся кольцо.** В Gio нет радиального градиента и сглаженной кисти; кольцо рисуется заливкой контура, а свечение — заранее посчитанной картинкой с альфой (слой прозрачности оставлял полосы). Экраны рендерятся в тестах через headless-бэкенд, см. README.

9. **Служба и инсталлятор.** Окно больше не владеет туннелем: служба запускает `control.Server`, окно подключается к pipe и получает готовое состояние в приветственном сообщении. Установщик — это тот же exe в режиме `--install`: копирует файлы в выбранную папку, создаёт службу с автозапуском, переносит настройки в `%ProgramData%` (ACL только SYSTEM и администраторы), пишет SID установившего пользователя для pipe, делает выбранные ярлыки и запись удаления. `ByeByeRKN-Setup.exe` — мастер на Gio: папка установки с «Обзор…», ярлыки в «Пуск» и на рабочем столе, автозапуск при входе, запуск после установки. Манифеста `requireAdministrator` нет: Setup сам перезапускает себя через UAC с `--elevated`, поэтому его тесты запускаются без прав, а отмена UAC показывается понятным сообщением. Удаление сначала посылает окну событие `Quit`, чтобы оно сняло маршруты, затем останавливает службу и уносит exe из папки через переименование в TEMP.

10. **Файлы, занятые запущенным приложением.** Обновление поверх установленной версии сначала закрывает окно, затем останавливает службу, и только потом копирует exe и DLL. Удаление переименовывает работающий exe в `%TEMP%` и поручает `cmd` удалить его после выхода; иначе Windows не даёт стереть образ процесса.

## Известные ограничения

- **MASQUE отсутствует.** Пока Telegram проходит через российский выход, это не мешает. Когда он действительно перестанет отвечать, без альтернативного транспорта из Android (`MasqueRoute`) останется только предупреждение.
- **Установщик и exe не подписаны.** Windows покажет предупреждение SmartScreen; для распространения нужен сертификат подписи кода.
- **Служба одна на машину.** WARP-аккаунт и настройки общие для всех пользователей; окно пускает только установивший пользователь (SID в `%ProgramData%\ByeByeRKN\client.sid`). Переустановка под другим пользователем обновляет SID, но служба должна перезапуститься.
- **Real-time качество выхода не контролируется.** Проверяется только то, что трафик идёт через WARP; в Android есть более развитый мониторинг.
- Если службу убить принудительно (не через SCM), часть маршрутов может остаться. Команды ручной очистки есть в `windows/README.md`.
- Принудительное завершение процесса из диспетчера задач не даёт снять маршруты: WM_ENDSESSION приходит только при выходе из системы; служба при этом обрабатывает Stop/Shutdown корректно.

## Команды

Go находится по пути `C:\android\go\bin\go.exe`, но `go` из PATH тоже подходит.

```powershell
cd C:\projects\Dostup\windows
C:\android\go\bin\go.exe vet ./...
C:\android\go\bin\go.exe test ./... -count=1
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

Результат сборки:

```text
C:\projects\Dostup\windows\dist\ByeByeRKN.exe
C:\projects\Dostup\windows\dist\wintun.dll
C:\projects\Dostup\windows\dist\ByeByeRKN-Setup.exe
```

`build.ps1` берёт версию из `app/build.gradle.kts` и передаёт её в `ui.Version`. Иконка и манифест
уже встроены через `ui\rsrc_windows_amd64.syso`. Пересоздать их:

```powershell
python windows\make_icon.py
go run github.com/akavel/rsrc@latest -ico winres\app.ico -manifest app.manifest -o ui\rsrc_windows_amd64.syso
```

## Что требуется дальше

1. **Прогнать установку на чистой машине/ВМ**: Setup.exe → UAC → служба → ярлык → обычный запуск окна, затем удаление через «Программы и компоненты». В текущей среде не было прав администратора, поэтому служба проверялась только запуском `--service` из консоли и подключением окна к pipe.
2. **Проверить реальное подключение** через установленную службу: кольцо, статус, карточка, трей, закрытие окна в трей, «Выход», завершение сеанса Windows.
3. **MASQUE** — альтернативный транспорт для случаев, когда все AmneziaWG-выходы ведут в Россию.
4. **Подпись кода** для Setup.exe и ByeByeRKN.exe, иначе SmartScreen будет пугать пользователей.
4. По возможности — вынести в отдельный процесс только сетевые операции, оставив GUI обычным пользовательским процессом.
5. Мелочи UI: экран «Приложения» (раздельного туннелирования на Windows пока нет), проверка обновлений как в Android.
